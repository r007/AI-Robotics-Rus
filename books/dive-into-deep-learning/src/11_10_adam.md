# 11.10 Алгоритм Adam

В этой главе мы уже изучили множество эффективных методов оптимизации.
Прежде чем переходить к новому, вспомним их подробно:

* В разделе 11.4 мы узнали, что стохастический градиентный спуск эффективнее градиентного спуска при решении задач оптимизации.
* В разделе 11.5 мы узнали, что использование большего набора наблюдений в минибатче даёт дополнительную эффективность за счёт векторизации. Это ключ к эффективному параллелизму на нескольких машинах, нескольких GPU и в целом.
* В разделе 11.6 мы добавили механизм, который суммирует историю прошлых градиентов, чтобы ускорить сходимость.
* В разделе 11.7 мы использовали предобусловливатель, который эффективно вычисляется за счёт покоординатного масштабирования.
* В разделе 11.8 мы отделили масштабирование каждой координаты от управления скоростью обучения.

Алгоритм Adam (Kingma and Ba, 2014) объединяет все эти приёмы в один эффективный алгоритм обучения.
Неудивительно, что он стал очень популярным: это один из самых мощных и эффективных оптимизаторов, используемых в глубоком обучении.
Однако у него есть и проблемы. В частности, Редди и соавторы (Reddi et al., 2019) показали, что Adam иногда может расходиться из-за плохого контроля дисперсии.
В качестве доработки Захир и соавторы (Zaheer et al., 2018) предложили «быстрое исправление» для Adam под названием Yogi.
Ниже мы рассмотрим алгоритм Adam.

## 11.10.1 Алгоритм

Одна из ключевых составляющих алгоритма Adam — использование экспоненциально взвешенных скользящих средних для оценки первого момента (импульса) и второго момента градиента. То есть используются переменные состояния

$$\begin{aligned}
    \mathbf{v}_t & \leftarrow \beta_1 \mathbf{v}_{t-1} + (1 - \beta_1) \mathbf{g}_t, \\
    \mathbf{s}_t & \leftarrow \beta_2 \mathbf{s}_{t-1} + (1 - \beta_2) \mathbf{g}_t^2.
\end{aligned}$$

Здесь $\beta_1$ и $\beta_2$ — неотрицательные весовые параметры.
Обычно их выбирают равными $\beta_1 = 0.9$ и $\beta_2 = 0.999$.
То есть оценка дисперсии смещается гораздо медленнее, чем оценка импульса.
Заметим, что если инициализировать $\mathbf{v}_0 = \mathbf{s}_0 = 0$, возникает заметное начальное смещение.
Его можно устранить, воспользовавшись равенством $\sum_{i=0}^t \beta^i = \frac{1 - \beta^t}{1 - \beta}$.
Соответственно, нормированные переменные состояния получаются по формулам

$$\hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1 - \beta_1^t} \text{ и } \hat{\mathbf{s}}_t = \frac{\mathbf{s}_t}{1 - \beta_2^t}.$$

Теперь, имея корректные оценки, можно записать уравнения обновления.
Сначала мы перемасштабируем градиент очень похожим на RMSProp образом:

$$\mathbf{g}_t' = \frac{\eta \hat{\mathbf{v}}_t}{\sqrt{\hat{\mathbf{s}}_t} + \epsilon}.$$

В отличие от RMSProp, наше обновление использует импульс $\hat{\mathbf{v}}_t$, а не сам градиент.
Кроме того, из-за масштабирования с помощью $\frac{1}{\sqrt{\hat{\mathbf{s}}_t} + \epsilon}$, а не $\frac{1}{\sqrt{\hat{\mathbf{s}}_t + \epsilon}}$, результаты немного различаются.
На практике первый вариант работает чуть лучше, поэтому он и отличает алгоритм от RMSProp.
Обычно мы выбираем $\epsilon = 10^{-6}$, что обеспечивает хороший баланс между численной устойчивостью и точностью.

Наконец, выполняем простое обновление:

$$\mathbf{x}_t \leftarrow \mathbf{x}_{t-1} - \mathbf{g}_t'.$$

Если взглянуть на алгоритм Adam, его замысел становится очевидным.
Во-первых, импульс и масштаб явно выражены в переменных состояния.
Их довольно своеобразное определение позволяет убрать смещение (это можно исправить с помощью немного другой инициализации и условий обновления).
Во-вторых, комбинация двух слагаемых из RMSProp очень проста.
Наконец, явная скорость обучения $\eta$ позволяет управлять размером шага для решения проблем сходимости.

## 11.10.2 Реализация

Реализовать алгоритм Adam с нуля нетрудно.
Для удобства мы храним номер временного шага $t$ в словаре `hyperparams`.
Во всём остальном всё просто.

**MXNet:**

```python
%matplotlib inline
from d2l import mxnet as d2l
from mxnet import np, npx
npx.set_np()

def init_adam_states(feature_dim):
    v_w, v_b = d2l.zeros((feature_dim, 1)), d2l.zeros(1)
    s_w, s_b = d2l.zeros((feature_dim, 1)), d2l.zeros(1)
    return ((v_w, s_w), (v_b, s_b))

def adam(params, states, hyperparams):
    beta1, beta2, eps = 0.9, 0.999, 1e-6
    for p, (v, s) in zip(params, states):
        v[:] = beta1 * v + (1 - beta1) * p.grad
        s[:] = beta2 * s + (1 - beta2) * np.square(p.grad)
        v_bias_corr = v / (1 - beta1 ** hyperparams['t'])
        s_bias_corr = s / (1 - beta2 ** hyperparams['t'])
        p[:] -= hyperparams['lr'] * v_bias_corr / (np.sqrt(s_bias_corr) + eps)
    hyperparams['t'] += 1
```

**TensorFlow:**

```python
%matplotlib inline
from d2l import tensorflow as d2l
import tensorflow as tf

def init_adam_states(feature_dim):
    v_w = tf.Variable(d2l.zeros((feature_dim, 1)))
    v_b = tf.Variable(d2l.zeros(1))
    s_w = tf.Variable(d2l.zeros((feature_dim, 1)))
    s_b = tf.Variable(d2l.zeros(1))
    return ((v_w, s_w), (v_b, s_b))

def adam(params, grads, states, hyperparams):
    beta1, beta2, eps = 0.9, 0.999, 1e-6
    for p, (v, s), grad in zip(params, states, grads):
        v[:].assign(beta1 * v  + (1 - beta1) * grad)
        s[:].assign(beta2 * s + (1 - beta2) * tf.math.square(grad))
        v_bias_corr = v / (1 - beta1 ** hyperparams['t'])
        s_bias_corr = s / (1 - beta2 ** hyperparams['t'])
        p[:].assign(p - hyperparams['lr'] * v_bias_corr
                    / tf.math.sqrt(s_bias_corr) + eps)
```

## 11.10.3 Yogi

У Adam есть и свои проблемы: даже в выпуклой постановке он может не сходиться, когда оценка второго момента $\mathbf{s}_t$ «взрывается».
Захир и соавторы (Zaheer et al., 2018) предложили улучшенное обновление и инициализацию для $\mathbf{s}_t$.
В статье предлагается переписать обновление Adam следующим образом:

$$\mathbf{s}_t \leftarrow \mathbf{s}_{t-1} + (1 - \beta_2) \left(\mathbf{g}_t^2 - \mathbf{s}_{t-1}\right).$$

Всякий раз, когда $\mathbf{g}_t^2$ принимает большие значения или обновления очень разрежены, $\mathbf{s}_t$ может слишком быстро «забыть» прошлые значения.
Эффективное решение — заменить $\mathbf{g}_t^2 - \mathbf{s}_{t-1}$ на $\mathbf{g}_t^2 \odot \mathop{\mathrm{sgn}}(\mathbf{g}_t^2 - \mathbf{s}_{t-1})$.
Это и есть обновление Yogi: величина шага теперь не зависит от размера отклонения.

$$\mathbf{s}_t \leftarrow \mathbf{s}_{t-1} + (1 - \beta_2) \mathbf{g}_t^2 \odot \mathop{\mathrm{sgn}}(\mathbf{g}_t^2 - \mathbf{s}_{t-1}).$$

В статье авторы также предлагают инициализировать импульс не поточечной оценкой, а большим начальным минибатчем.

**MXNet:**

```python
def yogi(params, states, hyperparams):
    beta1, beta2, eps = 0.9, 0.999, 1e-3
    for p, (v, s) in zip(params, states):
        v[:] = beta1 * v + (1 - beta1) * p.grad
        s[:] = s + (1 - beta2) * np.sign(
            np.square(p.grad) - s) * np.square(p.grad)
        v_bias_corr = v / (1 - beta1 ** hyperparams['t'])
        s_bias_corr = s / (1 - beta2 ** hyperparams['t'])
        p[:] -= hyperparams['lr'] * v_bias_corr / (np.sqrt(s_bias_corr) + eps)
    hyperparams['t'] += 1

data_iter, feature_dim = d2l.get_data_ch11(batch_size=10)
d2l.train_ch11(yogi, init_adam_states(feature_dim),
               {'lr': 0.01, 't': 1}, data_iter, feature_dim);
```

## Резюме

* Adam объединяет множество приёмов оптимизации в довольно мощное правило обновления.
* Adam создан на основе RMSProp и дополнительно использует экспоненциально взвешенные скользящие средние (EWMA) для минибатчевых стохастических градиентов.
* При оценке импульса и второго момента Adam использует коррекцию смещения, чтобы компенсировать медленный старт.
* Для градиентов с заметно различающейся дисперсией могут возникать проблемы со сходимостью. Их можно смягчить, используя больший минибатч или переключившись на улучшенную оценку $\mathbf{s}_t$. Альтернативу предлагает Yogi.
