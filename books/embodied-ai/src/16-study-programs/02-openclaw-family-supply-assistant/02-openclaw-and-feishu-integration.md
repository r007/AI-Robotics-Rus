# Подключение OpenClaw и Feishu

Эта глава посвящена только цепочке подключения. Интерфейс и логику запасов здесь не разбираем.

## Что должно получиться после главы

Читатель должен понимать:

1. Какие конфигурации читает OpenClaw
2. Где хранятся учётные данные приложения Feishu
3. Почему синхронизацию со многомерной таблицей нужно настраивать отдельным слоем конфигурации

## Порядок чтения

Интеграционный слой OpenClaw сначала читает переменные окружения, а затем возвращается к локальному файлу `~/.openclaw/openclaw.json`.

Приоритет:

1. `OPENCLAW_FEISHU_APP_ID`
2. `OPENCLAW_FEISHU_APP_SECRET`
3. `OPENCLAW_FEISHU_NOTIFY_TARGET`
4. `OPENCLAW_FEISHU_NOTIFY_RECEIVE_ID_TYPE`
5. `OPENCLAW_FEISHU_BITABLE_APP_TOKEN`
6. `OPENCLAW_FEISHU_BITABLE_TABLE_ID`

## Что нужно подготовить

- учётные данные приложения в открытой платформе Feishu;
- доступный для записи локальный конфигурационный файл OpenClaw;
- открытые права на многомерную таблицу.

## Ключевые контрольные точки

- Если `appId` и `appSecret` пусты, уведомления и синхронизация завершатся ошибкой.
- Если настроена только цель уведомлений, но не заданы `appToken` и `tableId` многомерной таблицы, синхронизация запасов всё равно не запустится.
- Если конфигурационный файл записан в Windows в UTF-8 с BOM, Python может не прочитать JSON; лучше сохранять UTF-8 без BOM.
