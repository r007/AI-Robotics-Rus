# Фронтенд и чек-лист публикации

В этой главе описано, что должен показывать фронтенд домашнего помощника и какие файлы нужно проверить перед публикацией каталога `tuntunclaw` в открытом репозитории.

## Цель фронтенда

Фронтенд не нужно делать полноценной админкой магазина. Его задача — показать читателю понятную демонстрационную цепочку:

1. текущие запасы;
2. статус низкого остатка;
3. статус напоминаний Feishu или синхронизации таблицы;
4. вход для заказа в один клик;
5. результат последнего выполнения задачи.

## Блоки фронтенда

- Поле ввода задач: для задач на естественном языке
- Блок статуса выполнения: этапы задачи OpenClaw
- Карточки запасов: товар, количество, порог и статус
- Блок синхронизации Feishu: настроена ли синхронизация, успешна ли она
- Блок журнала: последнее выполнение и сообщения об ошибках

## Проверка перед публикацией

Перед публикацией подкаталога `tuntunclaw` проверьте:

- не коммитим `.env`;
- не коммитим `sam_b.pt`;
- не коммитим `temp/`, `trash/`, `__pycache__/`;
- не коммитим отладочные изображения `mask_*.png`;
- не коммитим редактор сцен: `scene_layout_editor.py` и `SCENE_LAYOUT_EDITOR_README.md`;
- не коммитим локальные токены Feishu, ключи OpenAI и реальные внутренние адреса робота.

## Файлы, которые можно публиковать

- `.env.example`
- `README.md`
- `requirements-py311.txt`
- `frontend/`
- `inventory.py`
- `integrations.py`
- `workflow_hooks.py`
- `main.py`
- `openclaw_like/`

## Способ проверки

Перед отправкой выполните:

```bash
git status --short
git ls-files | grep -E "sam_b.pt|\\.env$|scene_layout_editor|__pycache__|temp/|trash/"
```

Вторая команда не должна выводить ничего.
