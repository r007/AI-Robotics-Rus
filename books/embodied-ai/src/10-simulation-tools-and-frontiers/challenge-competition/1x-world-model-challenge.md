# Соревнование 1X World Model

Прогресс в генерации видео может скоро сделать возможной оценку политик роботов в полностью обученных моделях мира. Сквозной обучаемый симулятор, который моделирует миллионы сред для роботов, заметно ускорит прогресс в универсальной робототехнике и даст полезный сигнал для масштабирования данных и вычислений.

Чтобы ускорить прогресс в симуляторах для обучения роботов, мы объявляем соревнование 1X World Model: нужно предсказывать будущие наблюдения от первого лица для [EVE Android](https://www.1x.tech/androids/eve). Мы предоставляем более 100 часов токенов изображений векторного квантования и исходные данные действий, собранные при управлении EVE, базовую модель мира (в стиле GENIE) и покадровый автоэнкодер MAGVIT2, который сжимает изображения в токены 16×16 и восстанавливает из них изображения.

Мы надеемся, что этот набор данных поможет исследователям робототехники, которые хотят работать в средах, рассчитанных на людей. Достаточно сильная модель мира позволит любому получить доступ к «нейросимулированной EVE». Конечная цель — задача оценки; промежуточные цели мы награждаем денежными призами, например за хорошее согласование с данными (соревнование по сжатию) и за генерацию правдоподобных видео (соревнование по сэмплированию).

## Задачи

Каждый пример — последовательность из 16 кадров от первого лица с робота, частота 2 Гц (всего 8 секунд). Нужно по предыдущим изображениям предсказать следующее изображение.

- **Соревнование по сжатию (призовой фонд $10k)**: предсказать дискретное распределение токенов следующего изображения.
  - Критерий: на нашем закрытом тестовом наборе сначала добиться **потерь временного teacher forcing ниже 8.0**.
- **Соревнование по сэмплированию (призовой фонд $10k)**: методы предсказания будущего не обязаны ограничиваться предсказанием следующего логита. Например, можно генерировать будущие изображения с помощью GAN, диффузионных моделей или MaskGIT. Критерии опубликуем позже.
- **Соревнование по оценке (скоро)**: дан набор из N политик $\pi_1, \pi_2, ... \pi_N$, где каждая политика $\pi_i(a_t|z_t)$ предсказывает токены действий по токенам изображений. Можно ли оценить все политики в «модели мира» $p(z_{t+1}|z_t, a_t)$ и сказать, какие политики окажутся лучшими?

Эти соревнования во многом вдохновлены [соревнованием по сжатию commavq](https://github.com/commaai/commavq). Подробности см. в разделе «Дополнительные детали соревнования».

## GENIE

В этом репозитории реализованы пространственно-временной трансформер и сэмплер MaskGIT, описанные в статье [Genie: Generative Interactive Environments](https://arxiv.org/abs/2402.15391). Обратите внимание: эта реализация обучается только на видеопоследовательностях, без действий (хотя добавить действия несложно, добавив эмбеддинги).

```
# Обучение модели GENIE
python train.py --genie_config genie/configs/magvit_n32_h8_d256.json --output_dir data/genie_model --max_eval_steps 10

# Генерация кадров из обученной модели
python genie/generate.py --checkpoint_dir data/genie_model/final_checkpt

# Визуализация сгенерированных кадров
python visualize.py --token_dir data/genie_generated

# Оценка обученной модели
python genie/evaluate.py --checkpoint_dir data/genie_model/final_checkpt
```

## Дополнительные детали соревнования

1. Мы предоставляем `magvit2.ckpt` — веса кодировщика/декодера [MAGVIT2](https://github.com/TencentARC/Open-MAGVIT2). Кодировщик позволяет токенизировать внешние данные, чтобы улучшить метрики.
2. В отличие от LLM, функция потерь здесь нестандартна: словарь токенов изображений поменялся в версии 1.0 (от 8 июля 2024 года). Вместо кросс-энтропии над логитами для 2^18 классов мы считаем кросс-энтропию предсказаний для 2 × 2^9 классов и суммируем её. Причина в том, что большой словарь (2^18) делает тензор логитов формы `(B, 2^18, T, 16, 16)` очень тяжёлым для памяти. Поэтому соревнование по сжатию рассматривает семейство моделей с факторизованным PMF вида p(x1, x2) = p(x1)p(x2). Для соревнований по сэмплированию и оценке факторизованный PMF является обязательным требованием.
3. Для соревнования по сжатию мы намеренно оцениваем отложенные данные при фиксированном факторизованном распределении p(x1, x2) = p(x1)p(x2). Хотя модель без факторизации, например p(x1, x2) = f(x1, x2), должна за счёт недиагональных членов ковариации x1 и x2 получать меньшие потери на тестовых данных, мы хотим поощрять решения, которые получают меньшие потери при фиксированной факторизации.
4. В соревновании по сжатию отправка может использовать только действия, которые произошли *до текущего кадра-подсказки*. Отправка может авторегрессивно предсказывать последующие действия для улучшения результата, но эти действия не будут поданы вместе с подсказкой.
5. Простой поиск ближайшего соседа с выбором следующего кадра из обучающего набора дал бы довольно хорошие потери и результаты сэмплирования на валидационном наборе, так как в обучающей выборке есть похожие последовательности. Однако мы явно запрещаем такое решение (закрытый тестовый набор накажет его).
6. Если правила соревнования нарушаются, мы не сможем выплатить награду лицам из стран, находящихся под санкциями США. Мы оставляем за собой право не выплачивать призы в соревновании.

### Детали метрики

Сценарии оценки различаются в зависимости от того, насколько много реального контекста получает модель. В порядке убывания контекста эти сценарии:

- **Полностью авторегрессивный**: модель получает заранее заданное число реальных кадров и авторегрессивно предсказывает все остальные кадры.
- **Временной teacher forcing**: модель получает все реальные кадры до текущего кадра и авторегрессивно предсказывает все токены текущего кадра.
- **Полный teacher forcing**: модель получает все реальные токены до текущего кадра, включая токены текущего кадра. Применим только для каузальных языковых моделей.

Например, рассмотрим предсказание последнего токена видео, который находится в правом нижнем углу 15-го кадра. В каждом сценарии модель получает такой контекст:

- Полностью авторегрессивный: первые $t$ токенов 16×16 — настоящие токены первых $t$ кадров, остальные токены генерируются авторегрессивно; $0 < t < 15$ — заранее заданное число кадров-подсказок.
- Временной teacher forcing: первые 15 токенов 16×16 — настоящие токены первых 15 кадров, остальные генерируются авторегрессивно.
- Полный teacher forcing: все первые (16×16×16 − 1) токенов — настоящие.

Соревнование по сжатию использует сценарий «временной teacher forcing».
