# Workspace Memory ATEC2026: постсоревновательный разбор

Дата обновления: 31.07.2026

## Границы работы

- Публичная точка входа на GitHub: `15-challenges/ATEC2026/`.
- Исходные проекты ATEC, кеши обучения, окружения и крупные checkpoint не попадают в историю Git Every Embodied.
- Крупные файлы, отфильтрованные данные, видео и полные снимки исходного кода отправляются на Hugging Face Datawhale с записью версии и SHA256.
- Самооценки внешних участников нельзя выдавать за официальные результаты.

## Факты о задачах

- Task A: прогулка по пересечённой местности.
- Task B: сбор мусора.
- Task D: толкание ящика и преодоление препятствий.
- Task E: уборка стола.
- Исследовательский акцент Task D: контакт с ящиком, прохождение ямы и платформы, конечный автомат, коррекция по LiDAR и восстановление с учётом оценки.
- Исследовательский акцент Task B: замкнутый контур RGB-D восприятия, выбора цели, подхода шасси, захвата или толкания, переноса и сброса в мусорную корзину.

## Наиболее полезные внешние решения

- Logic-TARS: основной референс для Task D. Зафиксированный commit: `b78c4afd1b84302fe8f88bcfd287eac64c33692c`.
- ZSN2024: референс для обучения, экспорта и адаптации Stage1 B2wPiper в Task B. Зафиксированный commit: `ee4e0eb97928754d9404a3acd5d644020ac7794c`.
- yma867: референс для YOLO + ByteTrack + обратной проекции глубины RGB-D в Task B. Зафиксированный commit: `e56a2a9e39c5231a91c0a8b1cce8ab1bc0e72403`.

## Важные границы

- Глобальная камера может использоваться для viewer, записи и офлайн-проверки; для официальных входов policy нужно соблюдать официальный контракт наблюдений.
- Размерности действий B2Piper и B2wPiper различаются, поэтому нельзя просто скопировать `solution.py`.
- Рост функции потерь при обучении не означает рост официальной оценки; нужно сохранять трассу оценки, видео и стадии сбоев.
- Модуль восприятия `yma867` не является полным контроллером сбора мусора: его точка входа содержит заглушку zero-action.
- Самооценка `32/100` у Logic-TARS пока не подтверждена независимыми официальными данными.

## Дисциплина экспериментов

1. Сначала проверить ID задачи, конфигурацию робота, ключи наблюдений и размерность действий.
2. Сначала выполнить проверку синтаксиса Python, загрузку модели, воспроизведение одного окружения и smoke-тест адаптера.
3. Менять за раз одну переменную и сохранять лучший известный checkpoint.
4. Оценка, видео и классификация сбоев важнее loss обучения.
5. Внешний код сначала проверить на лицензию и зафиксированный commit, и только потом переносить интерфейсы.
6. Перед публикацией проверить токены, абсолютные пути, внутренние IP, кеши, веса и необработанные логи.
