# ATEC2026 Task B: рабочая память (версия на китайском языке)

Дата обновления: 31.07.2026

## Назначение

Этот файл служит фактической памятью и границами работы при дальнейшем сопровождении публичного учебного материала по Task B. Здесь не хранятся приватные пути машины, учётные данные, веса моделей или исходные журналы соревнования.

## Подтверждённые факты

- Task B — Garbage Collection, платформа — B2-Piper.
- Замкнутый цикл задачи не сводится к навигации: включает поиск целей, сближение, операции манипулятора и захвата, проверку захвата, перенос, размещение в мусорной корзине и подтверждение оценщиком.
- Публичные наблюдения официального проекта в основном включают proprioception, LiDAR, головную RGB-D и концевую RGB-D.
- Нет оснований считать, что глобальная сторонняя камера окружения входит в стандартный официальный observation policy.
- Камеру окружения можно использовать для локальной записи, глобальной отладки и выравнивания отладки, но она не может давать координаты цели во время работы.
- Истинные позы объектов, ID объектов, внутренний список объектов симуляции и внутренние состояния оценщика допустимы только для диагностики без влияния на политику.
- Показатели подхода, касания и контакта не заменяют физическую проверку захвата, подъёма и размещения.

## Наиболее полезные публичные решения

Опубликованы навигация Task B, фиксация концевой камерой, калибровка манипулятора, классификатор и документы по обучению; это ближайшая к полной структуре Task B публичная реализация.
- Clear fork: [StevenLiudw/Clear_ATEC2026_Simulation_Challenge](https://github.com/StevenLiudw/Clear_ATEC2026_Simulation_Challenge). Лучше подходит как справка по locomotion, приседанию и отображению действий B2-Piper.
- Lhy fork: [Lhy6900/ATEC2026_Simulation_Challenge](https://github.com/Lhy6900/ATEC2026_Simulation_Challenge). Главное — адаптер G1/GR00T, он не может напрямую заменить интерфейс управления B2-Piper Task B.
- Ссылки на ZSN2024 и yma867 уже зарегистрированы в [индексе публичных решений](../references/README.md): первый — для каркаса обучения, второй — как справка по RGB-D восприятию.

## Что нельзя записывать как выводы

- Наличие публичного демо не равно официальному итоговому результату.
- Самооценка рейтинга не равна официальной таблице результатов.
- «Касание» в видео не означает, что объект удерживается.
- Видно, что объект виден в камере окружения, — не значит, что политика законно его видит.
- Особенности другого робота — порядок суставов, внешние параметры камер, размерности действий и пороги награды — нельзя переносить напрямую.

## Дальнейший порядок работы

1. Заново сверить ключи observation, пространство действий, runner и оценщик по текущему checkout официального репозитория.
2. Сначала провести smoke-тест допустимых наблюдений в одном окружении, затем поиск с головной камерой и фиксацию концевой камерой.
3. Отдельно проверить относительное положение после захвата, высоту подъёма и критерий размещения в корзине.
4. Сохранять для каждого эксперимента commit, seed, версию окружения, официальный балл, видео и стадию сбоя.
5. Перед добавлением внешнего кода сначала проверить лицензию; предпочитать ссылки и фиксированные версии, а не копирование больших репозиториев.
6. Перед публикацией запускать `code/scan_public_release.sh` и `code/build_public_manifest.py`.

## Границы публикации

GitHub хранит учебные материалы, лёгкие скрипты, конфигурации, границы результатов и внешние ссылки. Датасеты Datawhale на HF хранят небольшой публичный архив, соответствующий учебному материалу. Ассеты, данные, checkpoint, исходные видео и приватные журналы соревнования попадают в публичный репозиторий только при явном разрешении на распространение.
