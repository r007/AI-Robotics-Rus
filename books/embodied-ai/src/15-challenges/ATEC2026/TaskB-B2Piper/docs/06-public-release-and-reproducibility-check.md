# 6. Публичный выпуск и проверка воспроизводимости

## 6.1 Разделение работы между GitHub и Hugging Face

GitHub хранит:

- учебные материалы и разбор проблем на русском языке;
- лёгкие скрипты проверки, конфигурации и описание границ результатов;
- исходные ссылки на внешние решения, лицензии и пояснения по переносу;
- код, который можно читать и проверять без ассетов соревнования.

Hugging Face хранит:

- публичный архив, соответствующий учебным материалам;
- небольшие обезличенные образцы и конфигурации, которые можно распространять;
- входы для крупных файлов, которые будут добавлены после получения разрешения.

Официальные ассеты симуляции, исходные видео, checkpoint и приватные журналы не получают права на распространение только потому, что лежат на HF. Перед загрузкой нужно проверить источник, лицензию и размер файла.

## 6.2 Чек-лист перед публикацией

- [ ] Нет токенов, паролей, закрытых ключей SSH и URL с аутентификацией.
- [ ] Нет домашних каталогов пользователей машины, смонтированных дисков, внутренних адресов и путей приватного runner.
- [ ] Нет официальных ассетов, приватных журналов и веса без разрешения.
- [ ] Ни камера окружения, ни истинные позы объектов или ID объектов не записаны в официальный observation.
- [ ] Для всех результатов указан тип доказательства и его ограничения.
- [ ] У внешнего кода есть ссылка на репозиторий, атрибуция автора и описание лицензии.
- [ ] Большие файлы не обходят Git LFS и не попадают в обычные blob Git.
- [ ] Пути в командах документации заменены на переменные `$ATEC_ROOT`, `$HF_REPO` и подобные.
- [ ] Описание оценки включает runner, seed, версию окружения и информацию об официальном оценщике.

## 6.3 Минимальный набор полей для воспроизводимого отчёта

Каждый воспроизводимый эксперимент должен записывать как минимум:

```text
commit
environment_version
runner
seed
robot_platform
observation_keys
action_space
policy_checkpoint
episode_count
official_score
physical_grasp_verified
placement_verified
video_paths
failure_code
```

Если в отчёте нет `physical_grasp_verified` или `placement_verified`, его можно описывать только как «подход / касание / локальный результат управления», но не как «полный успех сбора мусора».

## 6.4 Советы читателю

Сначала воспроизведите официальное минимальное окружение, и только потом поэтапно включайте поиск, фиксацию концевым эффектором, захват и размещение. Меняйте за раз один модуль; публикуйте вместе с успешными примерами и разбор неудач с методами исправления. Ценность учебного материала часто именно в описании граничных условий.
